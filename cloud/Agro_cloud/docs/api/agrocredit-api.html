Convenciones

Contrato del corte vertical de AgroCredit en AWS (demo de cloud computing). Todos los datos de la demo son ficticios.

Convenciones

  • Autenticacion: Authorization: Bearer <ID token de Cognito>. El rol sale del claim custom:rol.
  • Dinero: texto con 2 decimales (ej. "1.80"), en soles. Volumen: kg enteros.
  • Los identificadores de campana, oferta y foto son UUID generados por el cliente; sirven de clave de idempotencia.
  • Los POST de campana y oferta responden 202: el registro se procesa por cola. Un GET inmediato puede dar 404; reintentar hasta que aparezca.
  • Errores en formato application/problem+json con requestId.
  • Esta demo no tiene HTTPS ni limite de tasa (limitaciones documentadas).

Base de todas las rutas: http://<dns del balanceador>/api/v1 (la imprime python tareas.py desplegar). Swagger interactivo de la API desplegada: /api/docs.

Autenticación

El navegador inicia sesión contra Amazon Cognito con el protocolo SRP (usuario = DNI o RUC, clave = PIN de 6 dígitos) usando GET /config para saber a qué pool conectarse. Cognito entrega un ID token (JWT, 60 min) que va en Authorization: Bearer <token>. La API valida firma (JWKS), emisor, audiencia, vencimiento y que token_use sea id; el rol sale del claim custom:rol (agricultor o comprador), fijado al crear la cuenta e inmutable.

Escrituras asíncronas (202)

POST /campanas y POST /campanas/{campaniaId}/ofertas validan, encolan el registro en Amazon SQS y responden 202 con recursoId y la ruta a consultar. Una Lambda lo escribe en DynamoDB con escritura condicional: reenviar el mismo id no duplica (idempotencia). El cliente consulta la ruta hasta que deja de responder 404, normalmente en 1 a 2 segundos.

Errores

Todos los errores usan application/problem+json:

{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "la cosecha debe ser una fecha futura",
  "requestId": "3c9d0e6a-6f2b-4d0f-9a43-1f1f7c2b8e55"
}

El requestId también llega en la cabecera X-Request-Id y sirve para buscar la petición en CloudWatch Logs.

Plataforma

Lo usa el balanceador de carga para saber si un contenedor puede recibir tráfico.

GET Chequeo de salud

/api/v1/salud

Estado del servicio y de la tarea que responde

Público (sin token)

Sin autenticación. Devuelve el id de la tarea (contenedor) y su zona. El balanceador lo consulta cada 5 s: si un contenedor no responde 2 veces seguidas, deja de enviarle tráfico.

Respuestas

CódigoSignificadoDetalle
200OK

Servicio operativo

Respuesta 200

CampoTipoDescripción
estado obligatoriotexto
valores: ok
tareaId obligatoriotexto

Identificador de la tarea o contenedor que respondio.

zonatexto

Zona de disponibilidad donde corre el contenedor (ej. us-east-1a).

versiontexto

Ejemplo

{
  "estado": "ok",
  "tareaId": "3f2a9c1d8b7e4a6f9d0c1b2a3e4f5a6b",
  "zona": "us-east-1a",
  "version": "c8f329de711b"
}

curl -s "$URL/api/v1/salud"
